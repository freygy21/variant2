# ЛР5. Правила задаются при создании сервиса

Вариант: **Card**.

## Что дано

Конструктор сервиса игнорирует переданные правила и создаёт собственный стандартный набор. Основной метод `CardService.check()` также нужно реализовать; готовые проверки объектов и зависимостей не переписывайте.

## Задание

### Шаг 1. Сохраните зависимости и настройте сборку

В `CardService(repository, rules)` сохраняйте переданные правила как `tuple(rules)`, не пересоздавая их.

Перенесите создание стандартных правил в `build_service()`. Явно переданный набор должен сохраняться. Проверка `Card.availability(as_of)` остаётся обязательной.

### Шаг 2. Реализуйте `CardService.check()`

Получите карту, вызовите `availability(context.as_of)`, затем правила по порядку. Статус и срок нельзя обойти. Верните первый отказ либо `CheckResult(True)`.

### Шаг 3. Проверьте отказ и следующий вызов

Контрольный исполнитель сначала выбрасывает `DomainError("TEMPORARY")`, затем успешно работает. Первый вызов не повторяется автоматически и не меняет данные; второй использует того же исполнителя. `TEMPORARY` — код учебной проверки, не новая ветка бизнес-логики. Отсутствие зависимости проверяйте через `is None`, а не её истинность.

### Шаг 4. Обязательная практическая часть

В `CardService` реализуйте `check_dates(card_id, dates)` — кортеж `(date, CheckResult)` по результатам `check()` с `CardContext`. `allowed_dates(card_id, dates)` возвращает только даты разрешённых операций. Не повторяйте проверки срока действия и статуса карты.

## Примеры и границы

- Переданное правило возвращает `CARD_TEST_DENIED`; сервис сохраняет этот отказ.
- Изменение исходного списка не влияет на сервис, разные наборы допустимых типов независимы.
- Пустой набор не разрешает заблокированную или просроченную карту.
- Исключение правила передаётся вызывающему коду, а не превращается в разрешение.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).
