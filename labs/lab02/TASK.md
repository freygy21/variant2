# ЛР2. Состояние и срок действия карты

Вариант: **Card**.

## Что дано

Обычные операции работают, но объект пока допускает часть недопустимых переходов между статусами. Кроме того, последний день срока действия карты ошибочно считается просроченным.

## Задание

### Шаг 1. Защитите переходы состояния

Разрешены только следующие переходы: `activate()` — `NEW -> ACTIVE`; `block()` — `ACTIVE -> BLOCKED`; `unblock()` — `BLOCKED -> ACTIVE`; `close()` — `NEW/ACTIVE/BLOCKED -> CLOSED`. Любой другой вызов, включая повтор действия, должен завершаться `DomainError("INVALID_STATE")`.

Сначала проверяйте исходный статус и только потом меняйте `_status`. После отказа статус карты должен остаться прежним.

### Шаг 2. Исправьте границу срока действия

В `availability(as_of)` сначала проверяйте статус: `NEW -> CARD_NOT_ACTIVE`, `BLOCKED -> CARD_BLOCKED`, `CLOSED -> CARD_CLOSED`. Только для `ACTIVE` проверяйте дату. Карта просрочена при `as_of > expiration_date`; код отказа — `CARD_EXPIRED`.

Последний день срока действия включён. Проверка даты не меняет статус: просроченная активная карта остаётся `ACTIVE`.

### Шаг 3. Сохраните приоритет проверок

Если карта одновременно заблокирована и просрочена, результат должен быть `CARD_BLOCKED`. Правила должны находиться в `Card` и работать без `CardService`.

## Примеры и границы

- При `expiration_date=2030-04-30` дата `2030-04-30` допустима, `2030-05-01` даёт `CARD_EXPIRED`.
- Заблокированная просроченная карта возвращает `CARD_BLOCKED`.
- Закрытую карту нельзя активировать; повторная блокировка вызывает `INVALID_STATE`.
- После любого отказа состояние карты не меняется.
